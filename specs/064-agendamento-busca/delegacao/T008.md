# T008 — Rotas do agendamento e o comando do terminal

Spec: 064-agendamento-busca
Tamanho: minor

## Contexto

Leia: `specs/064-agendamento-busca/contracts/api.md` (o contrato inteiro), `spec.md` (US3, FR-009, FR-010) e
`data-model.md`. Já existem: `filtros.salvar_agendamento` e `filtros.efetivos(cfg)["agendamento"]`; em
`agendamento.py`, `proxima_agendada`, `ler_estado`, `ler_retomadas`, `cancelar_retomada`, `apagar_retomadas`; em
`dash/agendador.py`, `AGENDADOR` (com `_devida`); em `dash/buscador.py`, `BUSCA.estado()` (com `origem` e, na
retomada, `retomada`). No `dash/servidor.py`, veja como a aba Limpeza faz `GET`/`PUT /api/limpeza` (`_limpeza`,
`_estado_limpeza`) e como as rotas de escrita ficam só locais (`self._local()`); `tests/test_limpeza.py` tem um teste
de rota com servidor de verdade em porta livre. O comando `vagas.py limpar` mostra como um subcomando novo entra no
`argparse` do `vagas.py`.

## O que fazer

1. `agendamento.py`: `estado_para_pagina(agora, devida: bool = False, rodando: dict | None = None) -> dict` no formato
   do `GET /api/agendamento` do contrato, sem `pode_alterar`: `agendamento`, `proxima`, `hoje` (do evento "agendada"
   de hoje no histórico: `rodou`/`pulada`/`perdida`/`falha` com `em` e `motivo`; `devida` se `devida`; `rodando` se
   `rodando` é a busca agendada; None se nada disso), `retomadas` (lista: `nome`, `portal`, `proxima`,
   `em_espera_ate` pelo `vagas.fontes_em_espera([nome], pagina=False)`, `consultas` = len(faltaram), `descricoes` =
   len(banco.pendentes_de_descricao(portal)), `tentativas`, `criada_em`, `origem_busca`), `historico` (até 10) e
   `aviso_login` (portais com login ligados no config: `vagas.fontes_com_login_fora(nomes, pagina=False)`, juntando
   os avisos, ou None). Imports de `vagas`/`banco`/`filtros` dentro da função.
2. `dash/agendador.py`: `Agendador.estado(agora=None)` chama `agendamento.estado_para_pagina(agora, devida=...,
   rodando=BUSCA.estado() se a origem for "agendada")`.
3. `dash/servidor.py`: `GET /api/agendamento` → `{**AGENDADOR.estado(), "pode_alterar": self._local()}`;
   `PUT /api/agendamento` (local) → `filtros.salvar_agendamento(corpo)`; se `continuar` ficou falso,
   `agendamento.apagar_retomadas()`; responde como o GET; `ValueError` → 400 `{"erro": msg}`;
   `DELETE /api/agendamento/retomadas/<nome>` (local) → `cancelar_retomada`; 404 `{"erro": "não há retomada para
   este portal"}` se não havia; responde como o GET.
4. `vagas.py`: subcomando `agendamento` com `--ligar HH:MM`, `--desligar`, `--continuar {sim,nao}` e
   `--cancelar-retomada NOME`. Sem opção: imprime ligado/desligado e horário, "Continuar de onde parou: sim/não", a
   próxima busca, cada retomada ("LinkedIn: retoma às 14:00, faltam 2 consultas e 18 descrições") e o último evento.
   Com opção: grava (`filtros.salvar_agendamento`; `--continuar nao` também apaga as retomadas) e imprime o novo estado.
   Horário inválido: mensagem no stderr e código 2. Inclua o comando na docstring do topo do `vagas.py`.
5. Testes em `tests/test_agendamento.py` (classe nova `TestRotasEComando`): GET devolve o formato do contrato; PUT
   com horário inválido → 400; PUT `continuar` falso apaga as retomadas; DELETE de retomada existente → 200 e some;
   inexistente → 404; `vagas.py agendamento --ligar 25:00` → código 2; `--ligar 07:30` grava no config temporário.

## Regras

- Não faça commit nem push; não crie branch; não mexa em `.git`.
- Só os arquivos da lista acima. Precisa de outro? Pare e diga qual e por quê.
- Python só com biblioteca padrão; textos em português do Brasil.
- A suíte inteira continua verde: `python -m unittest discover -s tests`.
- Nada de dados pessoais, nomes de pessoa, empresas ou números do usuário no código ou nos testes.
- Não edite `dash/front/` (é build gerado), `config.json`, `perfil.md`, `.env` nem `dash/dados/`.
- Ao terminar, liste os arquivos que alterou e o que ficou de fora, se algo ficou.

## Critério de aceite

- As três rotas respondem no formato de `contracts/api.md`; as de escrita só deste computador.
- `vagas.py agendamento` mostra e muda o agendamento; horário inválido sai com código 2.
- `python -m unittest tests.test_agendamento` passa, e a suíte inteira continua verde.
