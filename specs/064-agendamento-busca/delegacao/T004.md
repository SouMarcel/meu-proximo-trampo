# T004 — agendamento.py: regras da busca agendada

Spec: 064-agendamento-busca

## Contexto

Leia: `specs/064-agendamento-busca/spec.md` (US1, FR-002, FR-002a, FR-003, Clarifications), `research.md` (R2, R3) e
`data-model.md` ("Agendamento", "Execução do relógio", "Histórico de buscas"). A configuração já existe em
`filtros.py` (`filtros.efetivos(cfg)["agendamento"]` → `{"ligado", "horario": "HH:MM", "continuar"}`). O histórico de
buscas já existe em `vagas.py`: `vagas.ler_historico()` → lista de `{"origem", "inicio", "fim", "situacao"}` (ISO, a
mais nova primeiro; `situacao` "rodando", "concluida", "falha", "cancelada", "erro"). Este módulo é só regra e
arquivo: não inicia busca nem thread (isso é a T005).

## O que fazer

Crie `agendamento.py` na raiz (ao lado de `vagas.py`), biblioteca padrão, com `agora: datetime` sempre recebido por
parâmetro (sem `datetime.now()` dentro das regras):

1. Constantes: `TOLERANCIA = timedelta(minutes=15)`, `JANELA_MANUAL = timedelta(hours=4)`,
   `ORIGENS_MANUAIS = ("pagina", "terminal", "chat")`, `MAX_EVENTOS = 30`, `CACHE = Path(__file__).resolve().parent /
   ".cache"` e `ARQ_ESTADO = CACHE / "agendamento.json"`.
2. `horario_de_hoje(ag: dict, agora) -> datetime`: hoje no `ag["horario"]`.
3. `manual_recente(historico: list[dict], h: datetime) -> dict | None`: a busca de origem manual cujo `inicio` está
   entre `h - JANELA_MANUAL` e `h` (inclusive) e cuja situação é "concluida" ou "rodando"; a mais nova delas.
4. `decidir_agendada(ag: dict, agora, estado: dict, historico: list[dict]) -> tuple[str | None, str | None]`:
   - `(None, None)` se `ag["ligado"]` é falso, se `estado.get("dia") == agora.date().isoformat()` ou se `agora < h`;
   - `("perdida", "o dashboard não estava ligado às HH:MM")` se `agora > h + TOLERANCIA`;
   - `("pulada", "busca manual às HH:MM")` se `manual_recente` achou uma (HH:MM = início dela);
   - senão `("rodar", None)`.
   (Quem chama decide esperar se outra coisa estiver rodando; a regra não sabe disso.)
5. `proxima_agendada(ag, agora, estado) -> str | None`: ISO `YYYY-MM-DDTHH:MM` da próxima busca: hoje no horário se
   ainda não passou de `h + TOLERANCIA` e o dia não consta em `estado["dia"]`; senão amanhã; `None` se desligado.
6. Estado em arquivo: `ler_estado() -> dict` (ausente ou quebrado: `{"dia": None, "historico": []}`),
   `gravar_estado(estado)` atômico (arquivo `.tmp` + `os.replace`, cria a pasta), e
   `registrar_evento(estado, evento: dict, dia: str | None = None) -> dict`: põe o evento no começo de
   `estado["historico"]` (até `MAX_EVENTOS`), e, se `dia` vier, grava `estado["dia"] = dia`; devolve o estado (não
   grava; quem chama grava).
7. Testes em `tests/test_agendamento.py` (classe nova `TestDecidirAgendada`, sem mexer nas existentes), com `CACHE` e
   `ARQ_ESTADO` trocados por `mock.patch.object` para uma pasta temporária: 08:00 ligado → às 08:00 e às 08:15 "rodar",
   às 08:16 "perdida", às 07:59 None; desligado → None; dia já registrado → None (mesmo depois de mudar o horário para
   mais tarde no mesmo dia); manual concluída às 07:30 → "pulada" com "07:30"; manual às 03:00 → "rodar"; manual
   cancelada às 07:30 → "rodar"; manual rodando desde 07:55 → "pulada"; busca de origem "retomada" às 07:30 → "rodar";
   `proxima_agendada` às 07:00 → hoje 08:00, às 09:00 → amanhã 08:00, com o dia registrado às 08:05 → amanhã;
   `registrar_evento` guarda no máximo 30, o mais novo primeiro; estado quebrado no disco → padrão.
