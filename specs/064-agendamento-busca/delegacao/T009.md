# T009 — Página: aba Agendamento, quadro do agendamento e origem no andamento

Spec: 064-agendamento-busca
Tamanho: minor

## Contexto

Este é o front React (branch `frontend-react`). O contrato do servidor está em `specs/064-agendamento-busca/contracts/api.md`
da worktree do back (`../mpt-064`); o essencial está resumido aqui:

- `GET /api/agendamento` → `{agendamento: {ligado, horario: "HH:MM", continuar}, proxima: "YYYY-MM-DDTHH:MM" | null,
  hoje: {situacao: "rodou"|"pulada"|"perdida"|"falha"|"devida"|"rodando", em?: string, motivo?: string | null} | null,
  retomadas: [{nome, portal, proxima, em_espera_ate: string | null, consultas: number, descricoes: number, tentativas:
  number, criada_em, origem_busca}], historico: [{tipo: "agendada"|"retomada", situacao, portal?, em, motivo?}],
  aviso_login: string | null, pode_alterar: boolean}`;
- `PUT /api/agendamento` com `{ligado?, horario?, continuar?}` → mesmo formato (400 `{erro}` com horário inválido);
- `DELETE /api/agendamento/retomadas/<nome>` → mesmo formato (404 sem retomada);
- o estado da busca (`EstadoBusca` em `src/types/api.ts`) ganha `origem` "agendada" e "retomada" e, na retomada,
  `retomada: {nome, portal}`; o `resumo` final ganha `bloqueados?: string[]` e `retomada_as?: string | null`.

Padrões a seguir: a aba Limpeza (`src/components/modals/LimpezaAba.tsx`, `src/services/api/limpeza.ts`) é uma aba do
`SearchFiltersModal.tsx` com fluxo próprio, fora do Salvar filtros: faça a aba Agendamento do mesmo jeito.
`src/components/AndamentoBusca.tsx` mostra o andamento; `src/App.tsx` monta, na aba Vagas Nacionais ("relatorio"), o
`painelBusca`, a `UltimaBuscaLinha` e o `CompletarDescricoes`. Visual e textos: siga os componentes vizinhos (Tailwind,
tema claro/escuro, português do Brasil, sem travessão).
